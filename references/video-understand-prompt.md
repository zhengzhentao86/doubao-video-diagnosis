# 视频理解分析指令模板（S5 主分析引擎）

本文件是喂给 `video-understand-router` 的分析指令模板。执行时把 `{视频信息}` 替换为真实信息，其余部分原样使用。

## 调用参数

```bash
mediakit-cli video video-understand-router \
  --video-urls <本地文件路径或URL> \
  --level Quality \
  --manual-option '{"need_audio": true}' \
  --scene editing \
  --prompt "<下方指令模板>"
```

- `level=Quality`：精细语义理解档位
- `manual_option.need_audio=true`：开启音频分析（BGM/音效/卡点才能"听"到）
- `scene=editing`：输出带精确时间戳的详细分镜信息
- 查询结果：`mediakit-cli shared query-task --task-id <task_id> --poll-complete`
- 结果在 `contents[0]`：模型的完整分析文本

## 分析指令模板（--prompt 的取值）

```
你是抖音电商短视频资深编导。请完整观看下面这条视频（画面+声音），
输出一份可用于"爆款归因和下一版优化"的结构化拉片分析。

视频时长：{时长}秒
品类：{品类，未知则写"未知"}
目标：{目标，如"引流直播间/直接带货/品牌种草"，未知则写"未知"}

请严格按以下结构输出，所有结论必须带精确到秒的时间戳：

## 一、总时长与结构
- 视频总时长、大致段落结构（开头/中段/结尾各自的时间区间和功能）

## 二、前15秒逐秒拆解（重点！权重最高）
- 按时间逐秒描述画面（人物动作/镜头内容/产品是否出现）
- 标注每一处"钩子"：视觉打断、冲突、悬念、反差具体在几秒出现
- 标注字幕/口播文字内容
- 标注卡点：画面切换是否卡音乐节拍

## 三、完整分镜时间线（scene=editing 重点输出）
- 每个镜头：起始时间-结束时间 | 景别（远景/中景/近景/特写）| 运镜（固定/推/拉/摇/移）| 画面内容 | 字幕/口播
- 标注关键事件：产品第几秒第一次出现、第几秒第二次露出、每次持续多久

## 四、声音与音乐分析
- BGM 类型（热门卡点/抒情/搞笑/紧张）和情绪匹配度
- 卡点分析：画面切换是否卡拍、产品出场有没有"咚/叮"音效
- 人声节奏：语速快慢、停顿位置、停顿处配什么画面
- 口播逐句时间戳（ASR 已给，这里补充情绪和重音）

## 五、节奏曲线
- 用文字描述信息密度随时间的变化：哪里密、哪里松、哪里可能流失用户
- 标注"可能的流失点"：哪几秒容易划走，为什么

## 六、九维诊断初步打分（按用户决策路径分组，每维 好/中/差 + 一句依据，必须挂时间点）

### 阶段一：停下来（0-3秒）
1. 开头留人结构（0-3s 是否有打断/冲突/悬念）

### 阶段二：看下去（3-30秒）
2. 利益点/损失感（是否让用户意识到"与我有关"）
3. 卖点表达（具体数字 vs 空泛形容词）
4. 节奏与信息密度（中段是否有松区/长镜头）

### 阶段三：相信（全片穿插）
5. 信任素材时机（真实产品/证据几点出现，全程AI还是有实拍）
6. 身份/答案位置（品牌/直播间是剧情答案还是片尾口号）
7. 任务聚焦度（一条视频讲几个核心任务/卖点）

### 阶段四：行动（结尾+合规）
8. 转化引导时机（几点开始引导购买/进房，是否自然）
9. 内容风险（绝对化用语、医疗功效暗示、低俗梗、身材焦虑，逐条标时间点）

## 七、三个"最"（用于报告重点提炼）
- 最抓人的 3 秒：哪3秒最可能留住用户，为什么
- 最可能流失的 3 秒：哪3秒最可能被划走，为什么
- 最值得保留的 1 个结构：下一条视频最该复制的点

注意：
- 前15秒的分析粒度必须细到"秒"，之后可以按镜头/段落
- 画面和声音都要分析，音乐和画面脱节的地方要明确指出
- 禁止笼统描述，每个判断都给出时间戳证据
```

## 使用说明

1. 分析结果返回后，用 `contents[0]` 作为"视频级理解基线"。
2. **帧图只做证据补充**：抽帧图用于在 HTML 报告里"挂时间点配图"，证明"第X秒画面确实是这样"，**不是分析来源**。
3. 互动数据（点赞/收藏/分享/评论）用于交叉验证模型结论：
   - 模型说"开头钩子强"但5秒完播率低 → 钩子可能只制造了好奇没制造"与我有关"
   - 模型说"音乐卡点好"但数据一般 → 音乐适配人群可能和产品人群不匹配
4. 如果模型输出与 ASR/OCR 时间戳冲突，以 ASR/OCR 为准核对，模型负责"理解"、工具负责"事实"。
